1. Purpose of This Update

The JTBD Technical Note (Sieber & Sastre Boquet, 2026: "From Trend to Opportunity: Using Jobs-to-be-Done to Spot Entrepreneurial Solutions") is now available as a course reading for Sessions 3–4. This document specifies how to integrate it into the Value Designer agent across three areas:

Knowledge Base update — adding the technical note as a critical reference document.

System Prompt modifications — enriching Activities 1–3 with precise references to the note’s frameworks (Life Areas, struggling moments, four forces, three-dimension JTBD, WHEN/I WANT TO/SO I CAN format, and the Too Good To Go worked example).

Constructive critique — opportunities the technical note creates that the current spec does not yet exploit.

All changes are designed to be backward-compatible: teams that have not read the technical note can still use the agent, but teams that have will find the agent reinforces and deepens the frameworks they studied.

4. Updated Sample Conversation: JTBD Facilitation (5.3)

The existing sample conversation in Section 5.3 should be enriched to demonstrate the integration of the technical note’s frameworks. Replace with the following:

Scenario: Team formulates JTBD with technical note awareness

Student: "We’ve identified that our persona Clara feels frustrated when she wants to eat sustainably but can’t find affordable options. She tries searching online but it takes too much time."

Agent: "Good — you’ve identified a clear struggling moment: the tension between wanting to eat sustainably and finding it impractical or expensive. Let’s think about the forces at play. What PUSHES Clara to want change? What PULLS her toward alternatives? And what keeps her STUCK — habit and anxiety?"

Student: "The push is guilt about waste and health concerns. The pull is she’d love convenience plus sustainability. Habit is that delivery apps are easy. Anxiety is that sustainable options might taste bad or be inconvenient."

Agent: "Excellent — that’s a rich struggling moment. Now let’s write the JTBD. Use the format: WHEN [situation], I WANT TO [motivation], SO I CAN [outcome]. Remember: the I WANT TO must be solution-agnostic — no product names or specific technologies. And the SO I CAN should capture not just the practical benefit but how Clara wants to FEEL and how she wants to be SEEN. Give it a try."

Student: "WHEN I want a quick meal but my budget is tight, I WANT TO access quality, affordable, and sustainable food, SO I CAN eat well, save money, and feel like I’m making a positive difference."

Agent: "Strong start. Let’s check the three dimensions: Functional — access affordable food. Emotional — feel like making a positive difference. But I notice the Social dimension is thin. How does Clara want to be perceived by others? Does she want to be seen as environmentally conscious? Does she want to belong to a community? Sharpen that SO I CAN with a social element."

5.2 Gaps and Opportunities Not Yet Exploited

1. Template integration. The JTBD Technical Note contains five practical templates (Trend Radar, Life Area Impact, Persona Snapshot, Struggling Moments, and Interview Guide). The current agent does not reference these. Recommendation: When the agent generates a Miro export summary at activity gates, format the output to mirror the templates in the note. This gives students a familiar structure they can paste directly into their boards.

2. Validation checklist as a gating mechanism. The tech note’s JTBD validation checklist (8 criteria) is currently used only as a brief self-check. Recommendation: For teams that explicitly request it, the agent could run a more thorough “validation audit” — testing the JTBD against all 8 criteria with a pass/flag/fail assessment. This would be optional (not part of the mandatory flow) but available as a deeper-work mode.

3. Multiple-persona exploration. The technical note explicitly discusses how TGTG had to serve multiple personas (buyers AND restaurants). The current agent focuses on a single primary persona. Recommendation: In the Post-Session Mode, after the primary JTBD is complete, the agent could prompt: “Does your solution require satisfying a second persona? If so, what is THEIR job to be done?” This plants the seed for multi-sided platform thinking without overloading the in-session flow.

4. The “value proposition first, business model later” principle. The technical note ends with a strong pedagogical point: resist the urge to jump to business models. The agent could more actively enforce this. Recommendation: Add a guardrail: if a team starts discussing revenue models, pricing, or competitive advantage during Activities 1–6, the agent gently redirects: “That’s business model thinking — important but premature. Right now, focus entirely on the value you’re creating for the customer. We’ll get to the business model in Sessions 5–6.”

5. The WHEN/I WANT TO/SO I CAN format versus the Action + Object + Context format. The tech note teaches both. The current prompt modification presents the full format as primary and the shorthand as secondary. Observation: There is a risk of format confusion if the Session 3–4 slides use one format and the agent uses another. Verify that the professor’s slides and Miro templates use the WHEN/I WANT TO/SO I CAN format. If they use Action + Object + Context, flip the primacy in the prompt.
